# 백남준 TV 퍼즐 인수인계

## 목표와 범위

- **결과물**: 백남준의 TV 조각 작업에 대한 오마주 웹 게임 "백남준 TV 퍼즐 (Paik TV Puzzle)". 퍼즐과 기억력을 합친 게임이다.
- **게임 개요**: 크기가 다른 TV 5대를 좌우·상하로 90도씩 돌려 면끼리 붙여 조형물을 만든다. CORRECT로 제출하면 새 모양은 +10점, 이미 제출한 모양은 UNCORRECT로 −5점이다.
- **배포**: GitHub Pages (https://steves460ng.github.io/paik-tv-puzzle/), 설치형 PWA로 오프라인 플레이 지원.
- **범위**: 게임 기능, 다국어(한/영), README 문서, 배포. 서버나 계정 기능은 없다. 모든 데이터는 플레이어 브라우저의 localStorage에 저장된다.

## 제약과 선호

- 소유자의 주 업무는 기획·분석·설계·글쓰기·문서·관리·리뷰다. **코드 작성과 수정은 명시적으로 지시받았을 때만** 한다.
- 소통 언어는 한국어다. 게임 문구는 기기 언어가 한국어면 한국어, 그 밖에는 영어로 나온다.
- 이미 낸 모양을 기억하는 재미를 지키기 위해 **잭팟 목표는 화면에 드러내지 않는다**. 근접 알림도 넣지 않는다.
- 숨은 잭팟 배치는 **랜덤**이어야 한다.
- README 기본 언어는 영어(`README.md`)이고, 한국어판은 `README.ko.md`다. 두 파일 맨 위에 언어 전환 링크가 있다.

## 확정된 결정

- **TV 5대**: XL 12×10×10, L 10×8×8, M 8×6×6, S 6×4×4, XS 4×4×4. 각 화면에 컬러바·노이즈·자석 TV·달·리사주 영상이 나온다.
- **회전**: 좌우(Y축)와 상하(X축) 90도. TV 한 대당 서로 다른 자세는 24가지다.
- **면 구분**: 화면, 뒤판, 다이얼면, 스피커면, 윗면, 밑면이 각각 다르게 생겼다.
- **연결 규칙**: 면 중심끼리 맞춰 붙인다. 겹치면 붙일 수 없다. 한 TV에 여러 대를 붙이는 가지 구조도 허용한다.
- **같은 모양 판정**: 버튼 순서가 아니라 최종 모양으로 판정한다. 전체를 돌려서 같으면 중복이고, 거울상은 다른 모양이다.
- **화면 구성**: 점수는 좌상단, 만든 모양 수는 우상단. 리셋은 두 번 눌러야 작동한다. 우측 상단의 도움말 버튼은 기기 언어에 맞는 README를 새 탭으로 연다.
- **잭팟**: 게임 시작과 리셋 때마다 숨은 배치 23개를 랜덤으로 뽑는다. ×2 10개, ×4 8개, ×8 4개, 잭팟 ×10 1개이고, 보상은 기본 10점 × 배수다.
  - 판정 방식: 숨은 배치마다 랜덤 seed가 있고, `hash(seed + 모양 signature) < 확률`이면 당첨이다.
  - 같은 게임 안에서는 같은 모양이 항상 같은 결과를 낸다.
  - 한 번에 여러 개가 걸리면 가장 높은 배수 하나만 적용하고, 찾은 배치는 소진된다. UNCORRECT에는 적용되지 않는다.
  - 당첨되면 폭죽과 함께 보상 점수가 크게 표시된다.
- **잭팟 확률 설정**: `index.html` 스크립트 맨 위의 설정 블록에서 바꾼다.
  - `JACKPOT_FACTOR = 0.3`
  - 기본 확률: ×2 1/8, ×4 1/20, ×8 1/60, ×10 1/100
  - 실효 확률: ×2 약 1/27, ×4 약 1/67, ×8 1/200, ×10 약 1/333
  - 설정을 바꾸면 숨은 배치를 새로 뽑고, 점수와 기록은 유지한다.
- **이전 판정 방식 폐기**: 처음에는 "면끼리 연결 조건"으로 판정했다. 확률을 정밀하게 조정할 수 없어서 hash 방식으로 교체했다.
- **PWA**: three.js와 폰트를 `vendor/`에 넣어 외부 CDN 없이 동작한다. 서비스 워커는 페이지 요청에는 network-first, 나머지 파일에는 cache-first로 응답한다.

**검증한 것**
- 같은 모양 판정: 전체 회전 시 같음, 거울상은 다름을 단위 테스트로 확인했다.
- hash 확률: 20만 회 테스트에서 목표 확률과 일치했다.
- 잭팟 체감 빈도 (FACTOR 0.3, 게임 2만 판 시뮬레이션):
  - 보너스 당첨률은 첫 10회 제출에서 37.8%, 91~100회에서 6.0%다.
  - 잭팟을 만날 확률은 100회 안에 약 26%다.
- 헤드리스 크롬 렌더링: 한/영 화면, 도움말 링크 주소, 데스크톱·모바일 레이아웃.
- 로컬 서버 PWA 테스트: manifest 오류 0건, 18개 파일 캐시. 오프라인 새로고침에서도 게임·three.js·폰트가 정상 동작했고 콘솔 오류는 0건이었다. 설치 가능성 검사에서 남은 항목은 테스트 브라우저가 시크릿 모드라는 것뿐이었다.
- 최종 커밋 `0df3154` 기준 GitHub Pages 배포 성공.

**검증하지 않은 것**
- 실제 휴대폰(iOS, Android)에서의 터치 조작과 PWA 설치.
- 배포된 실제 사이트에서의 오프라인 동작.

## 제안과 가정

- **실기기 조작성 (미검증)**: 가장 작은 XS TV는 폰에서 면을 탭하기 어려울 수 있다. 터치 영역을 넓히거나 확대 버튼을 넣는 개선안이 있다.
- **확률 조정안 (제안)**: 초반 보너스가 여전히 후하게 느껴지면, ×2의 `chance`만 낮춰 잭팟 확률을 유지하면서 초반 빈도를 줄인다.
- **iOS 저장소 (가정)**: iOS에서는 설치한 앱과 Safari 탭이 localStorage를 따로 쓴다고 보고 README에 그렇게 적었다. 실기기로 확인하지 않았다.

## 미해결 질문과 장애물

- 실기기(iOS, Android)에서 터치 조작과 PWA 설치·오프라인 동작을 확인해야 한다.
- 아티팩트 버전과 저장소 `index.html`이 서로 다르다.
  - 저장소에만 PWA 태그, 로컬 vendor 경로, 서비스 워커 등록 코드가 있다.
  - 아티팩트는 CDN을 쓰고, 서비스 워커를 쓸 수 없는 환경이라 PWA가 동작하지 않는다.
  - 앞으로 어느 쪽을 원본으로 삼을지 정하지 않았다. 현재 실제 배포본은 저장소 쪽이다.

## 다음 작업

1. 실제 휴대폰에서 배포 사이트를 열고 터치 조작, 홈 화면 설치, 비행기 모드 실행을 확인한다.
2. 1의 결과에 따라 XS TV의 터치 조작성을 개선할지 결정한다. 코드 수정은 소유자가 지시할 때만 한다.
3. 플레이 감각에 따라 `JACKPOT_FACTOR`나 각 등급의 `chance`를 조정한다.
4. `vendor/`, 아이콘 등 `sw.js` 목록에 있는 파일을 바꾸면, 같은 커밋에서 `sw.js`의 `CACHE` 값을 올린다 (`paik-tv-v1` → `paik-tv-v2`).
